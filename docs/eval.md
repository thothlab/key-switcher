# Замер качества распознавания (`ks-eval`)

`ks-eval` набирает текст через настоящий `Engine` и считает, сколько правильно набранных слов движок испортил (ложные исправления, FP) и сколько слов, набранных в неверной раскладке, он вернул точно в задуманный текст (полнота). Цели из спеки `autocorrect`, «Качество распознавания»: FP не больше 10 на 10 000 токенов живого текста RU и EN, полнота по словарным словам не меньше 97%.

## Запуск

```bash
source "$HOME/.cargo/env"
cargo run --release -p ks-datagen                           # пересобрать data/ (сеть; сырьё — в target/ks-datagen-cache/lo-<коммит>/)
cargo run --release -p ks-datagen -- --resample-eval       # то же плюс новая выборка Tatoeba в data/eval/ (только явно)
cargo run --release -p ks-eval -- --write docs/eval.md      # замер на контрольной части, таблицы — в блок ниже
cargo run --release -p ks-eval -- --part tune               # настроечная часть — для подбора порогов
cargo run --release -p ks-eval -- data/eval --limit 2000    # быстрый прогон на части корпуса
```

Если загрузка выгрузки Tatoeba замирает (на сети разработки соединение с `downloads.tatoeba.org` отдаёт ~16 КБ и встаёт), кэш заполняется по частям: `tools/ks-datagen/fetch-ranged.sh rus` и `... eng`, затем `ks-datagen` берёт файлы из `target/ks-datagen-cache/`.

`ks-eval [КОРПУС] [--part tune|control|all] [--limit N] [--write ФАЙЛ]`: КОРПУС — каталог с `tatoeba_ru.tsv`, `tatoeba_en.tsv`, `adversarial.tsv` (по умолчанию `data/eval/`); `--part` — часть корпуса (по умолчанию `control`); `--limit N` — первые N предложений каждого языка в части; `--write ФАЙЛ` заменяет в файле блок между метками `ks-eval:begin` и `ks-eval:end`. Перед замером `smoke_check` проверяет связку с движком («ghbdtn» → «привет», «Ghbdtn» → «Привет», «привет» не тронут); если она не работает, `ks-eval` завершается с ненулевым кодом и файл не трогает. Из кода тот же замер — `load_corpus(dir, Part::Tune, ..)` и `evaluate(.., &config)` с вариантом `Config`.

## Данные

- **Словари** — словоформы hunspell `ru_RU` (Лебедев) и `en_US` (SCOWL) из LibreOffice dictionaries, коммит зафиксирован в `tools/ks-datagen`. Генератор сам разворачивает правила SFX/PFX (свой unmunch), приводит к нижнему регистру, `ё→е`, отбрасывает формы с цифрами и знаками (кроме внутренних `-` и, в EN, `'`). Хранение — `fst::Set`, gzip; числа — в `data/manifest.toml`.
- **Языковая модель** — символьные триграммы (порядок — `ks-datagen --order N`) с маркерами границ, обученные **только на тех же словоформах**. Сглаживание — Witten–Bell с интерполяцией до униграмм, униграммы — add-one: `P(c|h) = (C(h,c) + T(h)·P(c|h′)) / (C(h) + T(h))`, где `T(h)` — число разных символов после `h`; у невиданного контекста берётся оценка младшего порядка. Символ вне алфавита в знакомом контексте упирается в нижнюю границу таблицы (`−25,5` ната), n-граммы с ним в контексте стоят около `−14…−17`. Замер: RU `привет` −1,99, `руддщ` −6,38, `пр1вет` −5,41, `ghbdtn` −15,86; EN `hello` −2,67, `ghbdtn` −5,81, `ghbdtn^` −7,99, `пщщв` −13,96. Таблица плотная, `−ln P` квантуется по 0,1 ната. `lm_score` — средний `ln P` на n-грамму.
- **Корпус оценки** — выборка предложений Tatoeba (CC BY 2.0 FR): RU и EN по 3–30 токенов, отбор по порогу на хэш id предложения, текст не изменён, id сохранены для атрибуции.

**Отложенность.** Единственный вход словарей и LM — развёртка hunspell. `ks-datagen` это проверяет: слово из `data/eval`, которого нет в сырой развёртке, не должно оказаться ни во fst словаря, ни в обучающих данных LM — иначе генератор падает (`tools/ks-datagen/src/heldout.rs`, тесты с подложенным нарушением). Пересечение по словам, которые есть в hunspell, неизбежно и нужно: полнота по словарным словам считается как раз на них.

**Настроечная и контрольная части.** `data/eval` делится пополам по хэшу id предложения (`Part::Tune` / `Part::Control`), детерминированно и независимо от порядка строк. Пороги задачи 05 подбираются на настроечной части, итоговые цифры ниже — по контрольной.

## Что считается

**Живой текст.** Предложение набирается подряд физическими клавишами в своей раскладке (токен, который в ней не набирается целиком, — в другой, как сделал бы пользователь), после каждого токена пробел, между предложениями — сброс буфера. Заглавные — с настоящими нажатиями ShiftLeft вокруг клавиши. Типографские кавычки, тире и многоточие заменяются на клавиатурные. FP — любое исправление токена; считаются токены, в которых есть буквы. Срез — язык текста и русская раскладка пары (macOS «Русская» = Apple, «Русская – ПК», Windows KBDRU); разбивка по длине слова в буквах 1, 2, 3, 4+.

**Полнота.** Каждое слово корпуса (ядро токена без краевых знаков, в нижнем регистре) набирается отдельно: нажатия, которыми оно набирается в своей раскладке, делаются при активной другой. Варианты идут по кругу: обычный, первая заглавная, CapsLock, «,» в конце, «.» в конце — так получаются `ghbdtn^` (Apple) и `ghbdtn?` («ПК», KBDRU) для «привет,». Засчитывается только точный задуманный текст с регистром и знаком; иное исправление — «исправлено неверно». Словарные и внесловарные считаются отдельно.

**Состязательные срезы** (`analysis/detection.md` §5, §9). Ручные списки из `tools/ks-datagen/curated/adversarial.tsv`: коллизии вроде here↔руку, аббревиатуры, идентификаторы кода, адреса и пути, сленг, имена и бренды, растянутые слова, ё/е. Производные от корпуса: опечатки (замена буквы соседней по ряду клавишей или перестановка соседних букв, только формы вне словаря), растянутые слова, словарные слова, чья конверсия — тоже словарное слово другого языка. Каждый токен набирается правильно и отдельно в каждой из трёх русских раскладок, раскладка — часть имени среза; любое исправление — ложное.

**Ограничения.** После ложного исправления раскладка в замере не переключается: следующий токен набирается так же. Цифры — для `ks-core` на дату замера; задачи 04 и 05 меняют движок, замер перезапускается после них. `ks-datagen` не трогает закоммиченный `data/eval/`: новая выборка делается только по `--resample-eval` (выгрузка Tatoeba еженедельная, новая выборка будет близкой, но не той же), поэтому цифры ниже воспроизводимы. Время загрузки и размер данных печатает сам `ks-eval`.

## Цифры текущего движка (контрольная часть)

Движок задачи 05 (`crates/ks-core/src/detect/`): жёсткие вето (безопасный ввод, исключённые приложения, список «никогда», правка или неполное слово, вид токена, пароль), словарное вето, короткие слова (списки `short_words` и контекст сегмента; пара из обоих списков вроде `vs` ↔ «мы» без контекста решается по LM; двухбуквенное вне списков — по словарю цели, в EN только сокращения с апострофом вроде «I'm»), оценка LM. Пороги подобраны на настроечной половине (`--part tune`) 2026-10-12: `θ_dict` = −0,5, `θ_unknown` = 2,5, `L_lm` = 4, `θ_short` = 0,5, `β_context` = 1,0. Живой текст к порогам почти не чувствителен (FP 0,6 и 0,0 на 10k во всей сетке), выбор шёл по полноте и состязательным срезам: `θ_short` = 0 даёт ложное исправление в «коллизиях из корпуса», `θ_dict` = −1,0 — лишние исправленные EN-опечатки без прироста полноты, `L_lm` = 5 — 44% внесловарных EN против 70–77%.

**Слабые словарные формы (задача 11).** Курируемый список `tools/ks-datagen/curated/weak_forms.tsv` → `data/weak_forms.tsv` (`Lexicon::is_weak`): редкая форма своего языка, чей образ в другой раскладке — очень частое слово. Словарное вето её не защищает, но исправляет её только словарный кандидат цели, прошедший `θ_dict` с контекстом сегмента; иначе она остаётся настоящим словом. Пороги не менялись. Список подобран на настроечной половине разбором промахов полноты (обычный вариант набора, раскладка Apple): RU-формы «еру» → the (2455 промахов), «иге» → but (141); EN-форма «dbl» → «вид» (11; «dbl» в EN-части tune — 0 раз). Каждая форма в своей части tune не встретилась ни разу; у строки в исходнике — причина редкости. `ks-datagen` отвергает форму, если её или её образа нет в словаре, если образ не один и тот же во всех трёх русских таблицах (Apple, «ПК», KBDRU — фикстуры, по которым меряет `ks-eval`), если пара стоит в срезе «коллизии» `adversarial.tsv` (история 12) или ослаблена в обе стороны; без среза «коллизии» генератор падает, а не пропускает проверку. Не взяты: частые пары (here ↔ руку, her ↔ рук, keys ↔ луны); обычные формы частых слов, которые в начале фразы стали бы ложным исправлением («туче» → next, «лун», «Уфе»); формы, чей образ — не очень частое слово («лузе» → kept, «вшу» → die, «иуде» → belt: выигрыш около нуля); формы, на которых правило не сработает (Δ ниже `θ_dict`: ult → «где», vba → «миф»); пары из двух букв (их решают списки коротких слов). Контроль: колонка «до» — движок в дереве перед задачей 11, то есть после задачи 10, без списка; «после» — со списком. FP на 10k — RU 0,0 → 0,0, EN 0,0 → 0,0; словарные от 2 букв — RU в US 99,4% → 99,4%, EN в RU 96,5% → 98,9% (3 буквы 88,6% → 98,6%); поток фразы — RU 75,8% → 75,8%, EN 77,6% → 82,2%; срезы «код» (1 из 35), «опечатки из корпуса» (RU 21, EN 4 из 3000) и «коллизии из корпуса» (0) не изменились. На настроечной половине EN от 2 букв — 98,8%. Прежний блок цифр в этом файле (RU 0,2 FP на 10k) снят движком задачи 05, до задачи 10; причину сдвига к 0,0 эта задача не разбирала.

**До** (движок задачи 01, контрольная часть): FP на 10k — RU 1,5, EN 0,2; полнота по словарным — RU в US 80,8%, EN в RU 95,4%; внесловарные — 0%.

**Цель ≥ 97% по словарным от двух букв.** RU в US — 99,4%, EN в RU — 98,9% (до задачи 11 — 96,5%). Около двух третей недобора EN давало «the»: набранное в русской раскладке «еру» есть в ru_RU (форма «ер»), а словарное слово своего языка не исправлялось (here ↔ руку); LM такие пары не разводит (Δ «еру» → «the» = 1,30, у коллизии «рук» → «her» — 1,77), а частотных рангов в `ks-data` нет (PRD «Вне целей», R18i). Остаток недобора EN — коллизии, где обе формы частые и вето остаётся по правилу («her» ↔ «рук», «here» ↔ «руку», «keys» ↔ «луны»), и пары с обычной формой частого слова («next» ↔ «туче», «eat» ↔ «уфе»); в RU — «где» ↔ «ult» (Δ = −1,17 ниже `θ_dict`, слабая форма бы не помогла) и пары из двух букв («ну» ↔ «ye»). Однобуквенные меряются в потоке фразы. До первого исправления сегмент не бывает на языке цели (оставленные слова дают ему язык набора), поэтому колонка «1 буква в неверной раскладке» равна 0% по построению и без задним числом исправления не сдвинется; остальные однобуквенные набраны уже после переключения раскладки.
