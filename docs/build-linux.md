# KeySwitcher для Linux: сборка, права, проверка

Бэкенд Linux (`crates/ks-linux`) одинаков для X11 и Wayland: нажатия читаются с клавиатур через
evdev (`/dev/input/event*`, **без захвата**), исправление печатается через виртуальную клавиатуру
uinput (`/dev/uinput`). Раскладка переключается средствами окружения, таблицы клавиш строятся
xkbcommon по именам раскладок, трей — StatusNotifierItem по D-Bus (`ksni`), без GTK.

**Состояние: вживую на Linux не проверено.** С машины разработки (macOS) проверены компиляция под
`x86_64-unknown-linux-gnu` (`cargo clippy`, `cargo check -p ks-app`) и чистая логика тестами на хосте
(`cargo test -p ks-linux`): коды клавиш, определение окружения, команды и ответы IPC, права,
поправки модели исполнения без захвата.

## Сборка

На Linux (x86_64 или aarch64), Rust 1.99+:

```sh
cargo build --release -p ks-app
install -Dm755 target/release/keyswitcher ~/.local/bin/keyswitcher
install -Dm644 scripts/linux/install-udev-rule.sh ~/.local/bin/install-udev-rule.sh
```

Системные библиотеки при сборке не нужны: X11 — чистый Rust (`x11rb`), D-Bus — `zbus`,
`libxkbcommon.so.0` загружается при запуске через `dlopen` (`xkbcommon-dl`). Во время работы
нужны `libxkbcommon` (есть в любом графическом окружении) и сессионная шина D-Bus.

С macOS: `cargo clippy -p ks-linux --target x86_64-unknown-linux-gnu` и
`cargo check -p ks-app --target x86_64-unknown-linux-gnu`. Исполняемый файл кросс-сборкой —
`sh scripts/linux/build.sh` (один раз: `brew install zig && cargo install cargo-zigbuild`): кладёт
`dist/linux/keyswitcher` (x86_64, glibc ≥ 2.31, переменная `KS_GLIBC`) и рядом
`dist/linux/install-udev-rule.sh`. Сборка с macOS проходит; файл на Linux не запускался.

## Права: разовое udev-правило

Без доступа к `/dev/input/event*` и `/dev/uinput` KeySwitcher не исправляет ничего; иконка
показывает «нужны разрешения», раздел «Разрешения» — одну команду:

```sh
sudo sh ~/.local/bin/install-udev-rule.sh
```

Команду приложение строит само: ищет скрипт рядом с исполняемым файлом или в
`../share/keyswitcher/`, иначе показывает путь в исходниках `scripts/linux/install-udev-rule.sh`.

Скрипт ставит `/etc/udev/rules.d/70-keyswitcher.rules` с тегом `uaccess` (ACL только для
пользователя активной локальной сессии, `analysis/platforms.md` §3.3) на клавиатуры, мышь, тачпад
и `uinput`, и `/etc/modules-load.d/keyswitcher-uinput.conf`. Откат:
`sudo sh install-udev-rule.sh --uninstall`. Альтернатива `uaccess` — группа `input`
(`sudo usermod -aG input $USER` и правило с `GROUP="input"` для uinput): доступ шире — ко всем
клавиатурам для всех процессов пользователя, в том числе вне активной сессии.

Риск `uaccess`: процесс, открывший `/dev/uinput`, держит дескриптор и после смены пользователя;
смягчение — `KillUserProcesses=yes` в `logind.conf`.

## Автозапуск

Переключатель в настройках пишет или удаляет `~/.config/autostart/keyswitcher.desktop`
(`$XDG_CONFIG_HOME/autostart`, если задан) с `Exec=` на текущий исполняемый файл. На «голом»
композиторе, запущенном из TTY без XDG autostart (часто Sway, Hyprland), добавьте запуск в конфиг
композитора: `exec keyswitcher` (Sway), `exec-once = keyswitcher` (Hyprland).

## Окружения

| Окружение | Смена раскладки | Приложение в фокусе (исключения) | Конвертация выделения |
|---|---|---|---|
| X11 (i3, Openbox, GNOME/Cinnamon на Xorg) | `XkbLockGroup` | `_NET_ACTIVE_WINDOW` → `WM_CLASS` | PRIMARY + ввод результата |
| KDE Plasma, Wayland | D-Bus `org.kde.keyboard /Layouts` `setLayout(u)` | нет | нет |
| KDE Plasma, X11 | D-Bus `org.kde.keyboard` | `WM_CLASS` | PRIMARY + ввод результата |
| Sway | IPC `input type:keyboard xkb_switch_layout N` | IPC `get_tree` (`app_id`/класс) | нет |
| Hyprland | IPC `switchxkblayout all N` | IPC `j/activewindow` (`class`) | нет |

**Не поддерживаются** (PRD «Вне целей»): GNOME на Wayland — у GNOME нет API смены раскладки,
приложение пишет в `--status` и лог «смена раскладки в этом окружении не поддерживается» и не
исправляет; labwc (Budgie, Xfce на Wayland) — нет внешнего способа; MATE — группа XKB не отражает
раскладку; Flatpak — uinput доступен только через `--device=all`. Исключения по приложениям на
Wayland в GNOME и KDE не работают: окно с фокусом там не узнать (`AppId` пустой).

Раскладки берутся из окружения (`_XKB_RULES_NAMES`, `getLayoutsList`, `get_inputs`,
`j/devices` — с физической клавиатуры, где есть пара; своя виртуальная клавиатура и Power Button
пропускаются); нужна пара «латинская (`us`/`gb`) + русская (`ru`, любой вариант)», иначе меню
говорит «Нужны раскладки RU и EN».

## Известные ограничения

Чтение без захвата (`EVIOCGRAB` не используется — так KeySwitcher не конфликтует с keyd и
input-remapper) означает, что каждое нажатие доходит до приложения раньше, чем его видит движок:

- **Нажатия во время замены не придерживаются.** Если печатать, пока KeySwitcher стирает и
  перепечатывает слово (единицы–десятки миллисекунд), буквы могут встать посреди замены.
- **Граница слова уже напечатана**: замена стирает слово вместе с пробелом или знаком и печатает их
  заново.
- **Границы Enter и Tab не исправляются**: после Enter строка могла уже уйти (чат, терминал),
  после Tab фокус мог перейти в другое поле; Backspace и повторная граница испортили бы чужой текст.
  Исправление по пробелу и знакам работает.
- **Ctrl+Z после исправления** доходит до приложения, и оно отменяет своё; отмена KeySwitcher при
  этом снимается, чтобы не отменить дважды. Для отмены исправления — ⇧⇧ или Pause.
- **Горячие клавиши доходят до приложения** (Pause, Shift+Pause, Ctrl+Alt+K): «проглотить» их нельзя.
- **Ввод до начала замены отменяет её**: любое нажатие (кроме модификаторов) или клик после
  нажатия, вызвавшего замену, и до её первого Backspace — замена не выполняется, ничего не стёрто,
  слово в работе сбрасывается (число стираемых символов устарело бы).
- **Зажатый модификатор**: uinput не может отпустить клавишу чужой клавиатуры, поэтому перед
  первым Backspace KeySwitcher один раз ждёт (не дольше 300 мс), пока пользователь отпустит Ctrl,
  Alt и Meta; всё ещё зажаты — замена не начинается, ничего не стёрто. Shift не ждётся: на
  Backspace он не влияет; буквы при зажатом Shift могут выйти в верхнем регистре. Всё, что нажала
  сама виртуальная клавиатура, отпускается после каждой клавиши, при ошибке записи и по окончании
  задания.
- **Смена раскладки** вместе с подтверждением укладывается в 500 мс: каждый вызов D-Bus, IPC или
  X11 получает только остаток срока. Не уложилась — замена печатается клавишами по актуальной
  раскладке окружения (если раскладка не сменилась, на экране остаётся исходное слово).
- **Одиночный Shift и сразу буква**: буква уже напечатана в прежней раскладке — KeySwitcher стирает
  её и печатает в новой.
- **Клик**: кнопки мыши и касание тачпада (`BTN_TOUCH`, «тап как клик» синтезирует libinput)
  сбрасывают слово в работе; касание без клика тоже сбрасывает — это безопасная сторона.
- **Запасной путь Unicode** на Linux — клавиши раскладки, набирающей текст: если раскладка не
  переключилась, клавиши цели печатают исходное слово, текст не теряется.
- **Конвертация выделения** — только X11: текст берётся из PRIMARY и печатается поверх выделения,
  если владелец PRIMARY — окно в фокусе или другое окно того же клиента X11; иначе (PRIMARY остался
  от другого приложения или фокус не определён) ничего не печатается. На Wayland нужен протокол data-control, клиента для него в сборке нет —
  действие не выполняется и пишется в лог (без содержимого).
- **Трей** на чистом GNOME не виден без расширения AppIndicator; управление — через
  `keyswitcher --settings`.
- **GNOME на Wayland**: в `TrayStatus` нет состояния «окружение не поддерживается», поэтому
  значок покажет «работает»; честный статус — в `--status` и логе.
- **Исключения на X11** сравниваются с классом окна (вторая строка `WM_CLASS`: `firefox`,
  `Alacritty`); встроенный список частично записан именами экземпляра (`gnome-terminal-server`)
  и `app_id` Wayland — такие записи на X11 не совпадут.
- **Паузы** `KEY_PAUSE_MS` = 2 и `SWITCH_PAUSE_MS` = 15 подобраны под macOS; на Linux их нужно
  проверить вживую.
- `--selftest` есть только на macOS.

## Ручная проверка в VM

Подготовка: Fedora/Ubuntu/Arch в VM с сессиями X11, KDE Plasma (Wayland), Sway, Hyprland; включены
раскладки `us` и `ru`. Собрать, поставить, выполнить `RUST_LOG=info keyswitcher` из терминала.

1. **Нет доступа к эмуляции ввода** (спека `app-shell`). До установки правила: `keyswitcher` →
   иконка «нужны разрешения»; `keyswitcher --settings --section permissions` → «Разрешения»
   показывают команду `sudo sh …/install-udev-rule.sh`. `keyswitcher --status` → оба права «нет».
2. Выполнить команду из п. 1, перезапустить KeySwitcher → `--status`: права «да», перехват жив,
   найдены раскладки, окружение названо верно.
3. **Исправление на каждой ОС** (спека `app-shell`), в каждой сессии: в текстовом редакторе в
   английской раскладке набрать `ghbdtn ` → в поле `привет `, активна русская раскладка.
   Индикатор раскладки окружения показывает русскую.
4. То же в русской раскладке: `руддщ ` → `hello `.
5. Граница Enter: `ghbdtn` + Enter → строка не меняется (известное ограничение).
6. ⇧⇧ сразу после исправления → вернулось `ghbdtn `, раскладка английская.
7. Одиночный Shift → раскладка сменилась; Shift и сразу `g` → `п`.
8. Клик мышью и тап по тачпаду посреди слова, затем допечатать → исправления нет.
9. Исключения (X11, Sway, Hyprland): меню трея «Не исправлять в <приложение>» → в нём `ghbdtn `
   остаётся; в другом приложении исправляется.
10. X11: выделить `Ghbdtn? rfr ltkf&`, Shift+Pause → `Привет, как дела?`. Wayland: в логе
    «конвертация выделения в этом окружении недоступна».
11. GNOME на Wayland: `--status` и лог — «смена раскладки в этом окружении не поддерживается»;
    набор не меняется.
12. Автозапуск: выключить в настройках → `~/.config/autostart/keyswitcher.desktop` удалён;
    включить → файл есть, после перелогина агент запущен.
13. Горячее подключение: подключить USB-клавиатуру при запущенном агенте → с неё исправляется
    (опрос раз в 3 с).
14. Откат: `sudo sh install-udev-rule.sh --uninstall` → файлы удалены.
15. **Не проверено: состояние XKB виртуальной клавиатуры на Sway и Hyprland.** Своё устройство
    uinput там — отдельная клавиатура (в Sway — возможно, в общей группе с физической). Проверить:
    (а) CaseFix без смены раскладки (случайный CapsLock: `пРИВЕТ ` → `Привет `) печатается в той
    же раскладке, что активна на физической клавиатуре; (б) при включённом CapsLock перепечатка с
    виртуальной клавиатуры даёт тот же регистр (состояние Lock общее или своё у устройства);
    (в) после смены раскладки командой окружения виртуальная клавиатура печатает в новой раскладке.
16. Зажатый Ctrl: в настройках назначить «отмена / конвертация слова» на `Ctrl+Alt+KeyK`, набрать
    `ghbdtn`, нажать Ctrl+Alt+K и держать дольше полсекунды → ничего не стёрто, в логе «замена не
    начата: зажат Ctrl, Alt или Meta»; отпустить сразу → слово сконвертировано.
17. Выделение (X11): выделить текст в одном окне, перейти в другое без выделения, Shift+Pause →
    ничего не вставлено.
